# 小肚兜上线运行与回滚手册

> 本手册是执行清单，不代表任何生产环境操作已经完成。支付、社区、AI、营养报告仍处于关闭状态。

## 1. 发布前阻断项

1. 在部署平台秘密存储中配置 `xiaodudou-server/.env.production.example` 所列变量，禁止把真实值写入仓库、镜像层、构建日志或工单正文。
2. 运行 `pwsh ./scripts/production-preflight.ps1`。任何失败都必须阻断发布，禁止跳过。
3. 运行仓库扫描、自测、后端 `clean verify`、前端 `npm ci`、测试、H5/微信构建以及生产依赖审计。
4. 微信小程序 AppID、AppSecret、合法域名、隐私协议和主体资质必须由真实运营主体完成验收；当前仓库不提供这些外部条件。
5. 画像加密密钥必须有受控备份和恢复演练。密钥丢失会导致既有画像不可解密；不得用更换密钥掩盖恢复失败。

## 2. 数据库备份与迁移

1. 在维护窗口前创建 MySQL 一致性备份，并记录备份时间、数据库实例、校验值、保管位置和负责人。不要把备份放进仓库或镜像上下文。
2. 在隔离实例实际恢复备份，执行表数、关键表行数和随机样本核验。只有“备份成功”而没有“恢复成功”不算完成。
3. 发布前执行 Flyway `validate`。V1–V7 是已发布迁移，禁止修改、repair 或通过改校验和解决冲突。
4. 新迁移只允许新增下一个版本并保持向前兼容。先部署能同时读旧/新结构的应用，再迁移数据，最后才清理旧结构。
5. 数据库迁移通常不可随应用镜像自动倒退。若新版本失败，优先回滚应用到仍兼容当前数据库结构的版本；只有经过单独评审和恢复演练，才允许数据库恢复。

## 3. 灰度与验收

1. 先把新版本部署到不接收公网流量的绿色环境，等待启动闸门、Flyway、liveness 和 readiness 全部通过。
2. 运行 `pwsh ./scripts/smoke-test.ps1 -BaseUrl https://候选环境域名` 验证公开探针；获得合成账号会话后，再以 `-Token` 参数验证鉴权菜谱接口。随后手工验证登录、收藏、打卡和注销；完成后清理合成账号与行为数据。
3. 按 5% → 25% → 50% → 100% 逐级放量，每级至少观察一个完整业务高峰或团队批准的观察窗口。任一阻断告警触发即停止扩量。
4. 微信登录并发验证必须确认同一 openid 只生成一条有效账号记录，限流返回 429，Redis 故障时登录返回 503 且不会继续调用微信。

## 4. 监控与告警建议

管理端口默认 8081，仅应由集群探针和监控网络访问。Actuator 只暴露 `health`、`info`、`prometheus`，健康详情不对外展示。

| 监控项 | 建议告警条件 | 处理方向 |
|---|---|---|
| readiness | 连续 3 次 DOWN 或 1 分钟不可用 | 检查 DB、Redis、连接池，停止放量 |
| HTTP 5xx | 5 分钟错误率 > 1% | 按 request-id 关联应用日志 |
| HTTP P95 | 核心接口 10 分钟持续超过已验收基线 | 检查 DB 慢查询、线程与池等待 |
| 登录失败/429 | 同来源或整体突增 | 排查攻击、微信故障、代理边界 |
| Hikari | active 接近 maximum、pending > 0 | 检查慢 SQL 和池容量，不盲目扩池 |
| Redis | 连接失败、命令超时、内存持续升高 | 检查实例、网络和过期策略 |
| JVM | 堆使用率、GC 停顿、线程数异常 | 检查泄漏与突发负载 |
| 主机/容器 | 磁盘可用 < 15%、重启/OOM | 清理日志、扩容并分析根因 |
| Flyway | validate/migrate 失败 | 阻断启动，禁止 repair 绕过 |

## 5. 应用回滚

1. 立即停止扩量并保存告警时间、版本、request-id 样本和变更范围；不要在事故群粘贴秘密或完整用户数据。
2. 确认上一应用版本能够读取当前数据库结构。若兼容，将流量切回蓝环境或部署上一镜像版本。
3. 等待上一版本 readiness 恢复，再按只读烟测和核心链路验收；确认错误率和延迟回落后才关闭事故状态。
4. 如果数据库结构不兼容，禁止直接执行旧 SQL 或删除新列。隔离流量，按已演练的备份恢复方案处理并升级为数据事故。
5. 回滚后保留现场证据，完成影响用户、时间线、根因、修复、测试缺口和预防项复盘。

## 6. 密钥轮换与事故响应

1. 微信 Secret、数据库/Redis凭据泄露时，先限制访问并在对应平台轮换，再更新部署秘密并滚动重启；旧值必须撤销。
2. 画像密钥轮换必须先实现带版本的重加密流程并验证回滚，不能直接覆盖旧密钥。轮换期间要保留旧版本密钥的受控恢复能力。
3. request-id 只用于关联，不包含账号、openid、code 或请求内容。日志只记录状态、耗时和错误类型。
4. 事故结束后验证仓库、镜像历史、CI日志和备份位置均未残留秘密。

## 7. 依赖审计口径

- 后端采用 Java 17、Spring Boot 3.5.16，并由其 BOM 管理 Flyway 等基础依赖；升级后必须保存 dependency tree 和全量测试结果。
- 前端是编译为静态资源/微信产物的工程，生产依赖审计必须为 0 high/0 critical。DCloud 编译器属于开发依赖；其上游告警必须单独记录并持续跟踪，不能用 `audit fix --force` 或不兼容覆盖隐藏。
- 锁文件必须来自官方 registry，CI 使用 `npm ci`，不得手工修改完整性哈希。
- 2026-08-21 本地复核：OSV Scanner 2.5.1 扫描后端有效依赖为 0 已知漏洞；`npm audit --omit=dev` 为 0 漏洞。完整前端开发树仍有 39 项（13 high、12 moderate、14 low），全部位于 DCloud 编译工具链；其精确 peer 要求 Vite 5.2.8，当前不能用强制覆盖安全升级，需跟踪 DCloud 兼容发行版。该风险不进入 H5/小程序运行产物，但开发机与 CI 仍应只处理可信源码并限制构建环境权限。

## 8. 容器构建与验证

1. 在仓库根目录执行 `docker build -t xiaodudou-server:候选版本 xiaodudou-server`。镜像必须是多阶段构建，运行用户必须为 `10001:10001`。
2. 用镜像检查命令确认用户、入口和暴露端口；禁止把 `.env`、本地配置、数据库备份或构建缓存复制进上下文。
3. 以 `SPRING_PROFILES_ACTIVE=prod` 且故意不提供生产配置启动一次，必须由生产安全闸门明确拒绝。此负向测试只能核验拒启行为，不能替代真实生产预检。
4. 候选镜像必须通过隔离环境 readiness、只读烟测和合成账号核心链路后才能灰度。日志目录或挂载点必须由非 root 用户可写，禁止为解决权限问题改回 root。
